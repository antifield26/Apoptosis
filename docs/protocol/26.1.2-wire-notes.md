**reference-observed + codec-tested, not yet verified against a real 26.1.2
client** (see the parity matrix's test-client rows).

not disconnected (fixed in Audit 01).

## 3. Framing and compression

```text
uncompressed: [VarInt length][packet id VarInt][data]
compressed:   [VarInt frame length][VarInt uncompressed length][zlib(id+data)]
              uncompressed length 0 ⇒ tail is raw (id+data)
```

Enforcement in `mc-protocol::framing`:
- frame length and uncompressed length ≤ 2,097,152 bytes (`MAX_PACKET_SIZE`,
  matching `valence_protocol/src/lib.rs:79-80`);
- `uncompressed length == 0` fallback accepted; otherwise the declared length
  must be ≥ threshold (vanilla "badly compressed" rejection) and decompression
  output must match it exactly (bomb defence);
- the reassembly buffer is capped, so a client that never completes a frame is
  rejected, not buffered forever.

`SetCompression` is sent immediately before `LoginSuccess`; both directions
switch codecs at that point (`mc-network::connection::run_login`).

## 4. Network NBT

- Root tag is **nameless** (no root name bytes).
- Strings are Java **modified UTF-8** with a `u16` length prefix (NUL as
  `C0 80`; supplementary chars as surrogate pairs).
- Witnesses: the 26.1.2 jar's own `net.minecraft.nbt.StringTag.write` →
  `DataOutput.writeUTF`, measured on a JDK 25 probe
  (`writeUTF("\0") = 00 02 C0 80`, `writeUTF("\uD83D\uDE00") = 00 06 ED A0 BD ED B8 80`);
  corroborated by Minestom `BinaryTagTypeImpl.writeNameless` + `STRING_IO_UTF8`,
  Valence `valence_nbt/src/binary/{encode.rs,modified_utf8.rs}` and Pumpkin
  `pumpkin-nbt`'s CESU-8 helper.
- Our implementation lives in **`mc-nbt`** (`crates/nbt/`), shared by the disk and
  network encodings (ADR-0002); `mc-protocol::nbt` is a re-export façade with the
  golden fixture `fixtures/protocol/nbt_literal_text.hex` and hostile-length tests.

## 6. Login/configuration sequence we implement

1. SetCompression (threshold 256 by default, `-1` disables).
2. LoginSuccess(uuid, name, properties=[] for offline).
3. `LoginAcknowledged` → configuration.
4. Server config burst: `select_known_packs` (minecraft/core/<version>) →
   `update_enabled_features` (minecraft:vanilla) → `registry_data`
   (dimension_type: overworld) → `registry_data` (worldgen/biome: plains) →
   `update_tags` (empty) → `finish_configuration`.
5. Client ack → play: `login` (JoinGame) + chunk cache center/radius.

## 7. Open items (must resolve before compatibility claims)

1. **Registry element schema (26.1)**: the dimension/biome NBT in
   `mc-network::registry_data` is authored from the 26.1 datapack JSON shapes
   and is *provisional*; a real client may require additional fields
   (`attributes` coverage, clock/timeline registry interaction). Verify with a
   real 26.1.2 client, then move from "provisional" to "verified" and record
   the capture.
2. **Real-client capture**: no real client exists in this environment; the
   test client (`mc-test-support::client`) verifies the wire codec and server
   state machine but not client acceptance.
3. **Online mode**: encryption request/response + session verification are
   not implemented; `online_mode = true` fails startup by design.
